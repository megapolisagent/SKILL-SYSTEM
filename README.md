# Skill System

Библиотека профессиональных Skills — не папка случайных файлов, а система, которая помнит: что есть, для чего, откуда взято, что реально проверено, а что отправлено в архив.

## Что это

Skill — переносимый метод, который можно поставить в любого агента: формат тот же открытый стандарт (`SKILL.md`), что использует Anthropic, Cursor, Google. Skill System — не сам метод, а то, что вокруг него: где методы хранятся, как понять, что они делают, откуда взяты, проверены ли, актуальны ли ещё.

## Зачем

Потому что «папка с хорошими файлами» и «библиотека, которой можно доверять» — разные вещи. Skill получает и удерживает статус на основании доказательств, а не факта, что кто-то когда-то сказал «норм». Если Skill изменился после проверки — система сама это видит и предупреждает. Если он больше не нужен — не удаляется, а откладывается в архив с полной историей, доступный снова, если понадобится.

## Как устроена

```text
Новый Skill
     │
     ▼
Исследование ─── что он делает, откуда, какие есть альтернативы в мире
     │
     ▼
Сравнение с тем, что уже в библиотеке
     │
     ▼
        Решение владельца библиотеки
        /                          \
   не нужен сейчас              нужен
        │                          │
        ▼                          ▼
    📦 Archive                📚 Active Library
   (не удалён,                     │
    можно вернуть)                 ▼
                          используется, отслеживается на изменения
                                    │
                                    ▼
                     изменился/устарел → пересмотр
```

Три роли, не смешиваются:

- **Исследователь** — изучает мир, сравнивает найденный Skill с тем, что уже есть и с альтернативами снаружи, приносит факты. Не решает и не кладёт Skill в библиотеку сам.
- **Skill System** (этот репозиторий) — хранит библиотеку, проверяет структуру каждого Skill, следит за изменениями, показывает, что есть.
- **Будущие агенты** — берут готовые Skills из библиотеки. Пока не построены — это следующий, отдельный этап.

## Как пользоваться

- **Хочу посмотреть, что уже есть** — открыть `index.html`, вкладка «Библиотека».
- **Ищу Skill для задачи** — там же: поиск или фильтр по направлению (CORE / RESEARCH / WRITING / STRATEGY / ENGINEERING / DESIGN).
- **Нашла новый Skill** — добавляется в `skills/`, проходит структурную проверку, получает источник и направление. Появляется в библиотеке честно как непроверенный, пока не пройдёт исследование.
- **Хочу понять, нужен ли он** — если это Skill из внешнего мира (не написан нами), сравнивается с альтернативами; результат сохраняется рядом со Skill (`comparison.md`) и виден в карточке.
- **Хочу посмотреть архив** — вкладка «Архив» в Explorer. Ничего не удаляется навсегда, всё возвращаемо.
- **Хочу добавить свой Skill** — см. [CONTRIBUTING.md](CONTRIBUTING.md).

## Открыть интерфейс

**Живая версия (без clone):** [megapolisagent.github.io/SKILL-SYSTEM](https://megapolisagent.github.io/SKILL-SYSTEM/)

Либо локально:

```bash
git clone https://github.com/megapolisagent/SKILL-SYSTEM.git
```

Открыть `index.html` — двойным кликом или через браузер (`file://`). Сервер не нужен, работает офлайн. Живая версия — тот же файл, просто отданный GitHub Pages по прямой ссылке; обновляется каждый раз при `git push` в `main`.

## Документация

- [`CONTRIBUTING.md`](CONTRIBUTING.md) — как добавить/проверить Skill, формат, работа с CLI, разработчику.
- [`SKILL-SYSTEM.md`](SKILL-SYSTEM.md) — архитектурное решение: что построено и почему, техническая модель.
- [`SKILL-SYSTEM-STRESS-TEST.md`](SKILL-SYSTEM-STRESS-TEST.md) — проверка модели на реальных Skills, что подтвердилось, что изменили по факту.

## Структура репозитория

```text
SKILL-SYSTEM/
├── README.md                    ← этот файл
├── CONTRIBUTING.md               ← как пользоваться, для разработчика
├── SKILL-SYSTEM.md               ← архитектура
├── SKILL-SYSTEM-STRESS-TEST.md
├── index.html                 ← интерфейс, открыть в браузере
├── LIBRARY.md                    ← тот же каталог текстом (для агентов, grep)
├── registry.json                 ← внутренние данные, не редактируется руками
├── scripts/skillctl.py           ← CLI
└── skills/<имя>/
    ├── SKILL.md                  ← сам Skill
    ├── evidence.json             ← источник, категория, история проверок (внутренние данные)
    ├── comparison.md             ← если сравнивался с мировыми альтернативами
    └── (остальное — что было у оригинала: scripts/references/assets)
```
