## Базовый чеклист

- [ ] Workflow зафиксирован — все слои определены
- [ ] Источники данных определены по каждому слою
- [ ] Входные параметры системы зафиксированы
- [ ] Capabilities map заполнена по всем измерениям: **Skills / MCP / модели / внешние API и интеграции / инфраструктура (где и как физически исполняется — локально/облако/отдельный процесс) / браузер-автоматизация (если задача требует, иначе явно «не нужна») / orchestration paths** — инициатива Engineer, не ответ на вопрос владельца. Инфраструктура и браузер-автоматизация добавлены владельцем 2026-08-13 по итогам ревизии старого MAIN_ENGINEER (там — 7 осей capability map); честно: внешне подтверждённого 7-осевого стандарта индустрии не нашлось — расширение принято инженерным решением владельца, не как проверенная чужая практика.
- [ ] Naming: каждое имя модуля ограничивает scope и запрещает нецелевое расширение. Предпочитать конкретное над абстрактным. Имя отвечает на вопрос: «что здесь разрешено — а что уже нарушение архитектуры?»
- [ ] Separation by instability source: модули с разными API/rate limits/failure modes/lifecycle — раздельно. Не объединять разные источники нестабильности из соображений «удобства».
- [ ] Necessity/Reuse: решает ли эту же задачу уже существующая способность/Skill? Если да — это расширение (Extend before Create), не новая сущность; явно назвать, почему существующего недостаточно.
- [ ] Problem Fidelity: соответствует ли предлагаемое решение исходному намерению владельца (зафиксированному дословно тексту задачи), или в процессе исследования задача незаметно подменилась? Проверяется независимо от автора решения — не самопроверка исполнителя.

## Reliability Architecture

**Обязательно**, если агент относится к одной из категорий:
- client-facing система
- система, принимающая решения
- аналитика
- financial / reputation-sensitive workflow

Не применять к простым utility-агентам.

Если применимо:
- [ ] Deterministic/AI граница зафиксирована явно по каждому слою
- [ ] Hallucination control — механизм определён
- [ ] Agent separation — один или несколько агентов, обосновано
- [ ] QA: кто проверяет, по какому критерию
- [ ] Review loop: как отклонения возвращаются в систему

## AI Reasoning Boundaries — универсальный принцип

**AI имеет право:**
- интерпретировать данные, прошедшие через детерминированные слои
- формулировать выводы и нарратив
- ранжировать аргументы
- адаптировать под контекст

**AI не имеет права:**
- добавлять новые факты
- делать утверждения без источника
- придумывать тренды
- использовать вероятностные предположения при отсутствии данных

**При отсутствии данных:**
- некритичный фактор — пропустить молча
- критичный фактор — пометить явно как отсутствующий
- заполнять пробел предположением любого вида запрещено
