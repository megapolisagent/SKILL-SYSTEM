## Базовый чеклист

- [ ] Workflow зафиксирован — все слои определены
- [ ] Источники данных определены по каждому слою
- [ ] Входные параметры системы зафиксированы
- [ ] Stage 1 scope определён — что входит, что отложено
- [ ] Capabilities map заполнена по всем 7 измерениям:
      Skills / MCP / Integrations / Infra / Browser / APIs / Orchestration paths
      (инициатива архитектора, не ответ на вопрос Марии)
- [ ] Naming: каждое имя модуля ограничивает scope и запрещает нецелевое расширение.
      Предпочитать конкретное (cian_client) над абстрактным (retrieval, utils, data).
      Имя отвечает на вопрос: «что здесь разрешено — а что уже нарушение архитектуры?»
- [ ] Separation by instability source: модули с разными API / rate limits /
      failure modes / lifecycle — в разных файлах.
      Не объединять разные instability sources из соображений «удобства».
- [ ] Необходимость (Necessity/Reuse): решает ли эту же задачу уже
      существующий principle/skill/capability? Если да — это расширение
      (Extend before Create), не новая сущность; явно назвать, почему
      существующего недостаточно.
- [ ] Problem Fidelity: соответствует ли предлагаемое решение исходному
      намерению пользователя, или в процессе исследования произошла
      незаметная подмена задачи, уровня абстракции или цели? Проверяется
      независимо от автора решения — не самопроверка исполнителя.

## Reliability Architecture

**Обязательно** если агент относится к одной из категорий:
- client-facing AI system
- система принимающая решения
- аналитика
- financial / reputation-sensitive workflow

Не применять к простым utility-agents.

Если применимо:
- [ ] Deterministic/AI граница зафиксирована явно по каждому слою
- [ ] Hallucination control — механизм определён
- [ ] Agent separation — один или несколько агентов, обосновано
- [ ] QA: кто проверяет, по какому критерию
- [ ] Review loop: как отклонения возвращаются в систему

## AI Reasoning Boundaries — универсальный принцип

**AI имеет право:**
- интерпретировать данные, прошедшие через детерминированные слои
- формулировать выводы и нарратив
- ранжировать аргументы
- адаптировать под контекст клиента

**AI не имеет права:**
- добавлять новые факты
- делать рыночные утверждения без источника
- придумывать тренды
- ссылаться на несуществующие сигналы
- использовать вероятностные предположения при отсутствии данных

**При отсутствии данных:**
- некритичный фактор — пропустить молча
- критичный фактор — пометить явно как отсутствующий
- запрещено заполнять пробел предположением любого вида
