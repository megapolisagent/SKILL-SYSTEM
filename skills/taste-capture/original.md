# Taste Capture — метод накопления вкуса через реакцию, не через курацию

## Когда использовать

Нужно определить эстетическое, творческое или брендовое направление, и нет
готового брендбука или явно сформулированных предпочтений — вкус нужно
обнаружить, а не изобрести за человека.

## Метод (4 слоя)

**1. Gap Analysis, не пересборка**
Сначала — Retrieve before Generate: что из нужного исследования уже существует?
Закрывать только реальный пробел, не переделывать сделанное (см. CLAUDE.md,
Retrieve before Generate / Extend before Create).

**2. Evidence Board**
Структурированная доказательная база, не готовые выводы:

```
Fact → Pattern → Candidate Principle → Design Decision
```

Каждый Candidate помечен источником и статусом явно. Design Decision наступает
только после подтверждения человеком — Claude не переводит Candidate в Decision
самостоятельно, даже если уверен, что прав.

Внутри Evidence Board — две разные подстадии, границу между которыми стоит
держать явной:

```
Evidence Board
├── Visual Synthesis    — палитра, форма, композиция, плотность, выбросы
│                         (потенциально автоматизируемо, см. self-taste ниже)
└── Semantic Synthesis  — вербальные наблюдения, гипотезы, принципы
                          (уникальная часть, не автоматизируется протоколом)
```

**3. Taste Swipe**
Быстрая реакция (❤️ цепляет / ❌ не моё / 🤔 не уверена) плюс свободный
комментарий на разнообразных, заведомо не предрешающих направление референсах.
Куратор (Claude) подбирает разнообразие источников, не подбирает под ожидаемый
результат. Разнообразие важнее объёма — 50 действительно разных примеров сильнее,
чем 200 из одной ниши.

Калибровка нагрузки: реакция + одно свободное поле на пример — не обязательная
многополевая форма на каждый пример. Эффект усталости в разметке снижает качество
поздних ответов быстрее, чем растёт качество от дополнительной структуры.

**4. Taste Capture — лестница обобщения**

Первые три ступени — те же, что «Лестница обобщения» в CLAUDE.md (Raw
Observation → Hypothesis → Recurring Pattern), без изменений, не повторяются
здесь текстом (см. CLAUDE.md → Эпистемические маркеры). Специфика этого
skill — четвёртая ступень:

```
Recurring Pattern
        ↓
Creative Territory — синтез поверх устойчивых паттернов
```

Дословная формулировка человека сохраняется как есть до всякой интерпретации.
Пересказ вместо цитаты — явно помечается как пересказ, не выдаётся за Raw
Observation.

## Важные калибровки (проверено на практике)

- Living document — не ждать "достаточно материала". Первые устойчивые паттерны
  проявляются уже после 10–15 качественных записей.
- Не форсировать глубокое исследование внешнего мира (моду, digital-агентства,
  архитектуру) раньше рабочего цикла — это отдельный, более медленный слой,
  не блокирующий базовое использование.
- Своя коллекция референсов (скриншоты пользователя) технически возможна прямо в
  инструменте через вставку из буфера — не требует отдельной инфраструктуры,
  раз артефакт уже интерактивен.

## Внешний референс — self-taste (протокол, не обязательно реализация)

Найден 2026-07-21 при исследовании экосистемы (`github.com/serenakeyitan/self-taste`).
В первую очередь автоматизирует визуально-систематический слой Evidence Board
(палитра, типографика, форма, плотность, настроение — хотя mood/dynamics у него
уже не чисто числовые признаки, там есть элементы интерпретации) — но **не**
подменяет семантический слой (принципы,
гипотезы, вербальные наблюдения вроде «дышит, не продаёт»). Пересечение частичное,
не полное — self-taste начинается там, где уже есть папка отобранных образов
(«❤️ Strong Signals»), и не участвует в самом обнаружении вкуса (Taste Swipe).

Ценность — на уровне протокола, не реализации (инструмент сам заявляет, что
работает и через текстовый прокси, то есть спроектирован как последовательность
шагов + правила агрегации, не как модель компьютерного зрения): консенсус между
разнородными образцами, явная пометка выбросов по имени файла с причиной (не
усреднять молча), постоянный артефакт (TASTE.md) как результат. Эти идеи можно
перенять даже без установки самого skill.

Статус: **Investigate**, не Adopt — недостаточно свидетельств широкого
использования. Вопрос для проверки не «заменяет ли он taste-capture», а «может
ли он (или его протокол) автоматизировать структурирование уже отобранных
референсов, сохранив архитектуру как есть».
