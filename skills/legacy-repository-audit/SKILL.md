# legacy-repository-audit
## Проверка старого/внешнего репозитория перед тем, как строить новое

> Собрано 2026-08-13 по итогам двух реальных прогонов в этой же сессии (старый `MAIN_ENGINEER`, затем `AI_OS`) — оба раза процесс был одним и тем же, изобретённым заново каждый раз. Второй прогон нашёл настоящую ошибку первого (неполный учёт находок, забытые пункты без объяснения) — этот Skill существует, чтобы третий раз так не повторился.

## Когда нанимают

Владелец называет конкретный старый/внешний репозиторий агента и просит проверить его — обычно перед тем, как строить новых агентов, чтобы не переизобретать то, что уже сделано или уже решено не делать.

## Когда нельзя использовать

- Разбор текущего, живого репозитория самого Engineer/Researcher — для этого есть `architecture-review`/`repository-design`, не этот Skill.
- Ревью кода перед доставкой — не про это.
- Задача не про целый репозиторий, а про один конкретный файл/вопрос — избыточно, читай файл напрямую.

## Входные данные

- Ссылка на репозиторий (обычно GitHub).
- Что уже известно о его происхождении, если что-то известно (не выдумывать, если неизвестно).

## Метод

### Шаг 1 — Клонировать, не трогая оригинал
Скачать read-only копию во временную папку (scratchpad). Никогда не писать в оригинал, не коммитить туда. Явно объяснить владельцу, что значит «клонировать» при первом упоминании в разговоре, если ещё не было — не просто назвать действие.

### Шаг 2 — Идентификация, отдельным сообщением, до глубокого чтения
Прочитать только входные/навигационные файлы (README/CLAUDE.md/дашборд/входная точка). Ответить на три вопроса и показать владельцу **до** перехода к шагу 3:
- Что это за агент/система?
- За что она отвечает?
- Как она связана с текущей системой — предшественник, замена, что-то отдельное, всё ещё живая или остановленная? Если неизвестно — спросить владельца прямо, не предполагать (найдено на практике: предположение «жива» или «мёртва» без вопроса — риск строить рекомендацию на неверной посылке).

### Шаг 3 — Глубокое чтение, по категориям, не по файлам подряд
Систематически, не выборочно: архитектура и принципы; Foundation-аналог (если есть); Skills; MCP/tools; модели и роутинг между ними; permissions; workflows/lifecycle; собственная история решений и самопроверок (decisions/changelog/retrospective — если есть, это самый ценный материал: показывает, что реально проверялось на практике, не только что задумано).

### Шаг 4 — Классификация каждой значимой находки, без исключений
**Записать список находок в файл в момент, когда он сформирован — не держать только в разговоре.** Найдено на практике 2026-08-13: список из пяти ценных находок был назван в чате, но при исполнении позже в том же разговоре часть выпала без единого слова объяснения — не потому что решили не брать, а потому что список жил только в памяти диалога, не в файле, который можно перечитать и сверить построчно. Разговор — не надёжное хранилище списка находок на потом; файл — надёжное. Файл — `workspace/<дата>-legacy-audit-<имя-репозитория>.md`.

Каждая находка — явно один из вариантов, не остаётся неклассифицированной:
- **Skill System** — воспроизводимая методика для любого будущего агента, независимо от того, инженерная она или предметная (маркетинг/дизайн/письмо и т.п.). Категория домена не решает, брать или нет — решает воспроизводимость и наличие доказательств.
- **Дом (Foundation)** — универсальный принцип, верный для любого агента вообще, не только для строящихся Engineer.
- **Engineer (свои правила)** — как Engineer сама работает, не Skill и не универсальный принцип.
- **Владелец решает сам** — контент предметной области (бизнес-цели, готовые агенты, профессиональная методика), Craft, не Engineering.
- **Не взято** — с явной причиной: уже есть эквивалент (назвать какой), не подтверждено практикой, устарело, или просто не хватило внимания при первом проходе (эта причина допустима, если честно названа, а не скрыта).

**Перед тем как объявить учёт находок полным** — свериться с общим списком того, что было прочитано на Шаге 3, а не с тем, что запомнилось по ходу разговора: пропущенный пункт без объяснения — это не «взял что нужное», это неполный учёт, который придётся потом восстанавливать по прямому вопросу владельца (found the hard way, 2026-08-13).

### Шаг 5 — Внешние факты — проверять, не принимать на веру
Если находка сама ссылается на внешний источник (документацию, чужое исследование, конкретную технологию) — проверить источник напрямую (`WebFetch`/`WebSearch`) или через Researcher, если объём/неопределённость требует настоящего исследования. Не выдавать чужую цитату за подтверждённый факт без проверки — ни в свою пользу, ни против.

### Шаг 6 — Показать полную таблицу, дождаться решения, потом исполнять
Показать владельцу полный список находок с классификацией из Шага 4 — не куратированную выжимку из «самого важного». Внести изменения только после подтверждения. Если что-то уже сделано раньше независимо от этого разбора (проверить перед докладом, не предполагать) — сказать это прямо, не приписывать себе.

**Перед тем как начать исполнять подтверждённый список — открыть файл из Шага 4 заново и вычёркивать пункты по нему, не по памяти разговора.** Если между показом таблицы и исполнением прошло много реплик (в том числе не по этой задаче) — риск потерять пункт растёт, не снижается. Файл, не память диалога, — источник истины на этом шаге.

## Self Check («И что с того?»)

Если владелец после отчёта спросит «а что ещё не взяли и почему» — есть ли готовый, полный ответ без необходимости заново перечитывать репозиторий? Если нет — Шаг 4 не был доведён до конца.

## Checklist

- [ ] Клонировано read-only, оригинал не тронут
- [ ] Идентификация показана владельцу отдельно, до глубокого чтения
- [ ] Прочитано по категориям (архитектура/Skills/MCP/модели/permissions/decisions), не выборочно
- [ ] Список находок записан в файл `workspace/` в момент формирования, не оставлен только в разговоре
- [ ] Каждая находка классифицирована — Skill System / Дом / Engineer / владелец / не взято-с-причиной
- [ ] Исполнение подтверждённого списка вычёркивается по файлу, не по памяти разговора
- [ ] Проверено, не взято ли что-то из находок уже раньше независимо (сверка с реальным регистром/файлами, не по памяти)
- [ ] Внешние ссылки в находках проверены, не принята чужая цитата без проверки
- [ ] Показана полная таблица, не выжимка
- [ ] Изменения внесены только после подтверждения владельца
