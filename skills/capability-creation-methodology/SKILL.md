# capability-creation-methodology
## Воспроизводимый путь от «нужна экспертиза в X» до спроектированной Capability

> Статус: v0.1, гипотеза, не подтверждённый Skill. Marketing — первый реальный
> тест-кейс (решение владельца, 2026-07-25). Критерий подтверждения —
> в конце файла, тот же принцип, что у `conversion-method/SKILL.md`.

---

## Место в существующей системе — не параллельный путь

Этот skill не заменяет `idea-calibration.md` и не дублирует его Шаги 0, 1,
3–7 (Trigger, Problem Definition, Alternatives, Trade-offs, Routing Decision
+ Falsification, Decision Point, Handover) — они выполняются как есть, без
изменений.

Этот skill — специализация **Шага 2 (World Research)** для конкретного
случая: тема требует не разовой справки, а исследования целой незнакомой
экспертной области (роль/профессия, не инструмент). Идея-калибрация говорит
«исследуй пропорционально масштабу» — этот файл отвечает на вопрос «что
именно значит исследовать целую профессию», раскладывая один шаг на
проверяемые фазы вместо одной прозаической строки.

Capability/Skill/Agent Design (фазы 8–9 ниже) не изобретают новый формат —
routing идёт через `idea-calibration.md` Шаги 3–7, Validation — через
существующую 7-мерную Capabilities map `architecture-review.md`.

---

## Назначение

Дать AI_OS воспроизводимый путь от «проекту нужна экспертиза в незнакомой
области» до спроектированной (не построенной) Capability/Skill/Agent-связки,
основанной на проверяемых источниках, не на архитектурной догадке.

## Когда нанимают

Idea Calibration Шаг 0 сработал (Impact/Uncertainty/Complexity, хотя бы одна
high), и конкретно триггер — «предложение нового агента/проекта» или «нужно
создать X» — а X относится к целой профессиональной области (маркетинг,
продажи, финансы, обучение, юриспруденция), не к точечному инструменту.

## Когда нельзя использовать

- Точечное расширение уже понятной области (правка внутри уже спроектированной
  Capability) — работает Fast Path idea-calibration.md напрямую
- Область, где Мегаполис/проект уже имеет built и используемого агента —
  Capability Evolution, не новое создание
- Пока не пройден Шаг 0 idea-calibration.md — этот skill не подменяет его

## Входные данные

- Тема (название экспертной области)
- Проект, для которого создаётся Capability (для Legacy-first Alarm — фаза 2)
- Доступ к World Research (Exa/WebSearch, per routing/registry.md)

## Метод

### Фаза 0 — Trigger check
`idea-calibration.md` Шаг 0. Если не совпал — стоп, этот skill не нужен.

### Фаза 1 — Problem Definition
`idea-calibration.md` Шаг 1, без изменений. Что сломано, для кого, в одном
параграфе.

### Фаза 2 — Legacy-first Alarm на файловой системе проекта (сразу после
Problem Definition, до любого внешнего поиска)
Активный grep/glob по всей структуре проекта — не только по уже известным
из разговора подпапкам, не мысленная проверка. Внутренний Source of Truth
задаёт контекст для внешнего исследования, не наоборот: если в проекте уже
лежит стратегия/TOV/фреймворк, они определяют рамку Фаз 3–7 с самого начала,
а не проверяются постфактум, когда внешний поиск уже проведён и потрачено
время. Прямой урок 2026-07-25: Foundation Strategy V1, TOV, КОНТЕНТ ЗАВОД
были найдены поздно (после того как внешнее исследование и часть проектных
решений уже были сделаны) — это стоило переделки, а не просто уточнения.
Найденный материал блокирует и переопределяет Фазы 3–7, не дополняет их.

### Фаза 3 — Domain Research
Обязательно ответить:
- какие роли/специализации существуют внутри профессии сегодня, чем
  отличаются друг от друга (не общий список — с диагностическим отличием
  каждой от соседних)
- что в профессии смещается/исчезает под давлением AI, что остаётся
  человеку — не предположение, источник
- есть ли прямой первоисточник модели, уже используемой проектом (проверить
  ДО сравнения с другими — если есть, он не один из вариантов, а Source of
  Truth, остальное подчинено ему, см. кейс Trust Equation/Maister)

### Фаза 4 — Market Scan
Существующие AI/SaaS-решения и агентные системы в этой области. Для каждого
значимого — не просто «существует», а статус: проверено (реальные метрики,
источник) vs. заявлено (маркетинговый текст продукта, не подтверждено).
Явно отмечать провалившиеся/дискредитированные подходы, не только успешные —
это тоже сигнал (пример из 2026-07-25: AI SDR полной автономии — реальные
репутационные провалы, не гипотетический риск).

### Фаза 5 — Open Source Research (обязательная, не подразумеваемая)
Отдельный, не пропускаемый шаг — не одна строка внутри приоритета
источников. Найти зрелые репозитории/архитектуры в этой области.

Для каждого найденного репозитория — обязательная верификация до цитирования:
не звёзды/форки/активность из сниппета поиска, а подтверждённые (WebFetch/
прямая проверка). Если верификация технически не удалась (сетевые
ограничения среды) — прямо сказать, что не удалось, не выдавать поисковый
сниппет за проверенный факт. Урок 2026-07-25: пропуск этой фазы целиком —
реальный, зафиксированный случай, не гипотетический риск.

### Фаза 6 — Methodology Research
Реальные фреймворки/методологии области — с явным отличием каждого от
соседних (не 10 похожих имён, меньше — но содержательно разных, per
Precision Over Recall).

### Фаза 7 — Knowledge Extraction
Не список источников — решение по каждому: что берём, что отклоняем, одна
строка обоснования на источник. Формат: «из X — берём Y, потому что Z».
Пустое «изучили X» без решения = фаза не завершена.

### Фаза 8 — Capability/Skill/Agent Design
`idea-calibration.md` Шаги 3–6: 3 альтернативы → Trade-offs → Routing
Decision + обязательная Routing Falsification → Decision Point.

### Фаза 9 — Validation & Handover
`architecture-review.md` (7-мерная Capabilities map) + `idea-calibration.md`
Шаг 7 (Handover, Bootstrap Sequence).

## Self Check («И что с того?»)

Если удалить результат этой методики — отличался бы он от того, что можно
было написать по памяти без единого реального источника? Явно проверить:
внешние источники реально использовались для **обнаружения**, или только для
**подтверждения** уже готового в голове списка? (Прямой урок 2026-07-25:
8 из 10 «найденных» экспертов оказались подставлены в запрос из предзнания,
не обнаружены нейтральным поиском — этот вопрос обязателен для каждого
прогона, не факультативен.)

## Обязательный лог

```
[CAPABILITY CREATION — PHASE LOG]
Тема: [домен]
Legacy-first Alarm: [что найдено в файловой системе проекта / ничего — до внешнего поиска]
Domain Research: [N ролей, диагностическое отличие каждой]
Market Scan: [N решений, проверено/заявлено]
Open Source: [N репозиториев, верифицировано/не удалось верифицировать]
Methodology: [N фреймворков, чем отличаются]
Knowledge Extraction: [источник → берём/отклоняем → почему, построчно]
→ далее idea-calibration.md Шаги 3–7 как есть
```

## Критерий подтверждения / опровержения гипотезы

**Подтверждение:** второй домен (не Marketing) проходит те же 9 фаз без
изменения структуры — только содержание другое.

**Опровержение:** второму домену требуется переписать сам порядок фаз, не
только их содержание — тогда это не один воспроизводимый метод, а
специфика Marketing, выданная за общую методологию.
