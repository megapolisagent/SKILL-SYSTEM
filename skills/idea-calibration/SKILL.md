# idea-calibration
## Глубокий путь калибровки — только для крупных решений

> Собрано 2026-08-13 — лучшее из своей лёгкой версии (`HOME.md`, «Вход в задачу») и полного протокола AI_OS (`skills/idea-calibration.md`). Лёгкая версия остаётся входным гейтом для всех задач без изменений — не заменяется. Этот Skill — то, что подключается дополнительно, когда сама лёгкая версия распознала крупное решение, а не любое high по одной из трёх осей.

## Когда нанимают

«Вход в задачу» уже сработал (хотя бы одна ось high), и решение конкретно про: новый агент/проект; изменение собственной методологии работы Engineer; редизайн, затрагивающий больше двух модулей/файлов устава.

## Когда нельзя использовать

- Обычная неопределённость, которую снимают 2-3 уточняющих вопроса — для этого «Вход в задачу» уже достаточен, этот Skill не подменяет его.
- Разовая задача без долгосрочных последствий, даже если Uncertainty high.

## Метод

### 1. Problem Definition
Один абзац: текущее состояние → желаемое состояние → кто испытывает боль (владелец/Engineer/собранный агент) → по возможности цифра. Не переходить дальше, если формулировка расплывчата.

### 2. World Research (если Uncertainty high)
Через Researcher, критерий достаточности фиксируется до запроса (уже практикуется, `OPEN_QUESTIONS.md`). Для решений этого масштаба — обязательная минимальная последовательность источников, не только первый найденный: первичный поиск → открытые реализации/репозитории, если есть → реальный опыт пользователей (форумы/сообщества), если решение касается практики, которой реально пользуются → официальная документация → синтез не менее нескольких реальных примеров, не один. Найдено на практике (AI_OS): без явного минимума research останавливается на поверхностном поиске, даже когда триггер уже сработал.

### 3. Три альтернативы
Не одна, не две — три. Для каждой: 2-3 строки описания + что нужно + время до рабочего результата.
- **A (Minimal)** — самый простой путь.
- **B (Scale)** — более амбициозный путь.
- **C (Hybrid)** — промежуточный.

### 4. Trade-offs
Таблица 3×3 (альтернатива × плюсы/минусы/риски). Отдельно назвать: какой самый простой, самый безопасный, быстрее всего даёт рабочий результат, сложнее всего поддерживать.

### 5. Routing Decision + Routing Falsification
Выбрать маршрут, документировать критерии/причину/риски/почему остальные отклонены. Затем обязательно — falsification, не пропускать даже если маршрут кажется очевидным:
- Почему это может быть НЕ нужно?
- Какие предположения под риском?
- Что говорит против выбранного пути?
- Можно ли проверить дешевле, чем полным решением?

### 6. Problem Fidelity — до решения, не только после сборки
Сравнить выбранный маршрут (шаг 5) с формулировкой из шага 1: это ещё та же задача, или в процессе исследования и альтернатив она незаметно подменилась? Это отдельная, более ранняя проверка, чем «Независимая проверка результата против исходной задачи» из `LIFECYCLE.md` — та происходит после того, как решение уже реализовано; эта — до того, как решение принято.

### 7. Decision Point
Yes / No / Experiment (2-недельный scope с exit criteria). Confidence: Low/Medium/High. Confidence Low → вернуться к шагу 2, не принимать решение на слабом основании.

## Обязательный лог (для записи в `DECISIONS.md`)

```
Problem: [одна строка]
Research: [источники + confidence]
Alternatives: A / B / C (названы кратко)
Routing Decision: [выбранный маршрут]
Routing Falsification: [assumptions at risk + case against]
Problem Fidelity: [совпадает с шагом 1 / расхождение — что именно]
Decision: Yes / No / Experiment
Confidence: Low / Medium / High
```

## Связь с уже существующими механизмами — не дублирует

- `HOME.md`, «Вход в задачу» — входной гейт для всех задач, не меняется. Этот Skill — не альтернатива ему, а то, что подключается дополнительно для крупных решений.
- `LIFECYCLE.md`, «Независимая проверка результата против исходной задачи» — проверка после сборки. Problem Fidelity здесь (шаг 6) — проверка до решения. Разные точки, не повторяют друг друга.
- `architecture-review` — следующий шаг после Decision: Yes, не часть этого Skill.
