# Tool Selection

## Principle

Правило выбора инструмента формулируется по категории задачи, а не по имени конкретного сервиса — если завтра сменится провайдер поиска или харнесс, принцип не должен сломаться вместе с ним. Пять категорий, которые встречаются в работе Engineer:

1. **Нужно узнать, что уже делает рынок** (мировая практика, готовый Skill, чужой репозиторий) → инструмент поиска/исследования.
2. **Нужно прочитать/изменить файлы репозитория, который собираем** → файловые и репозиторные инструменты.
3. **Задача многошаговая, требует отслеживания прогресса** → инструмент трекинга задач.
4. **Решение реально принадлежит владельцу** (не факт, который можно найти, а выбор с несколькими допустимыми ответами) → прямой вопрос владельцу, а не догадка.
5. **Задача большая, независимая, не обязана держать основной контекст занятым** → делегирование фоновому агенту.

Если задача не попадает ни в одну категорию, или под неё нет доступного инструмента — не подменяй догадкой: нет реального факта — пометь `[УТОЧНИТЬ]` и спроси.

## Implementation (в этой среде — Claude Code, исправлено 2026-08-12 после реальной ошибки)

**Ошибка, реально найденная и исправленная 2026-08-12**: предыдущая версия этого раздела утверждала «не предполагай доступность Exa/Firecrawl/Context7» и подавала это как единственный критерий — не рассматривать их. `claude mcp list` показал, что все три реально подключены и вызывались в этой же сессии. Причина ошибки — смешение двух разных вопросов в одно суждение. Дальше они разделены явно:

| Слой | Вопрос | Как проверить у себя |
|---|---|---|
| **Доступно** | Физически подключено прямо сейчас? | `claude mcp list` — не предполагать, проверить |
| **Принадлежит** | Закреплено за этим проектом (переедет с `git clone`)? | Есть запись в `.mcp.json` проекта? Если такого файла нет — значит нет, даже если «доступно» |
| **Разрешено** | Технически позволено вызывать? | `.claude/settings.json`/`settings.local.json`, `allow/ask/deny` |
| **Подходит для задачи** | Стоит ли использовать именно здесь? | Решение по категории задачи (раздел Principle выше), не по факту подключения |

Практический вывод: `mcp__exa__*`, `mcp__firecrawl__*`, `mcp__hackernews__*`, `mcp__youtube-transcript__*`, `context7` — могут не принадлежать агенту как проекту (нет `.mcp.json`), но это не значит «не рассматривать». Перед задачей категории 1 (мировой поиск/исследование) — проверить `claude mcp list`, не предполагать заранее ни доступность, ни недоступность.

**Вторая находка того же дня**: агент, имея инструмент реально доступным, может ни разу его не вызвать — не из-за явного запрета, а потому что искал через `ToolSearch` с запросом, называющим уже известные имена, а не открытым вопросом. Открытый запрос (например, «инструмент для веб-поиска») с большей вероятностью вытащит альтернативу, которая не пришла в голову по привычке. Перед задачей категории 1, если результат первого инструмента слабый — стоит хотя бы раз попробовать открытый `ToolSearch`, не только называть уже знакомое.

При свежем развёртывании агента сессионные MCP (не задекларированные в `.mcp.json`) не появятся сами — это не изменилось, только уточнено, что «не появится само» ≠ «не нужно рассматривать, если появилось».

**Явно не проверено в моменте**: специализированный GitHub-MCP, Playwright/Browser — проверь через `ToolSearch`/`claude mcp list` перед использованием, не по памяти этой записи. Если недоступны — `WebFetch`/`Bash`+`gh` как fallback для GitHub-специфичных задач.

## Governance по инструменту/модели — когда да, когда нет, ограничения, альтернатива

Добавлено 2026-08-13 (Engineer, по итогам ревизии старого MAIN_ENGINEER) — усиливает раздел выше. Раздел выше отвечает «доступен ли инструмент технически»; этот раздел отвечает на другой вопрос — «годится ли он для этой конкретной задачи», по каждому инструменту отдельно, не одним общим суждением. Ровно та ошибка, которую этот раздел закрывает — инструмент был доступен, но не рассматривался, потому что правило судило о нём одним общим суждением, а не по месту.

| Инструмент/модель | Когда использовать | Когда не использовать | Ограничения | Альтернатива |
|---|---|---|---|---|
| `WebSearch` | Быстрый факт, недавнее событие, не важен точный текст конкретной страницы | Нужен точный текст известной страницы, а не поиск | Может не найти нишевый/специализированный источник | `WebFetch` на известный URL, `Exa` для смыслового поиска |
| `WebFetch` | URL уже известен, нужен именно его текст | URL не известен — это задача поиска, не чтения | Не ищет, только читает по адресу | `WebSearch`, `Exa` |
| `Exa` (`mcp__exa__*`) | Смысловой поиск, когда прямые ключевые слова не находят нужное; альтернативные формулировки той же задачи | Простой фактологический вопрос, который `WebSearch` решает быстрее и дешевле | Внешний MCP, может не принадлежать проекту (нет `.mcp.json`) — доступность проверять `claude mcp list`, не предполагать ни да, ни нет | `WebSearch`; открытый `ToolSearch`, если результат первого инструмента слабый |
| `Firecrawl` | Нужен контент/структура целого сайта или нескольких страниц сразу, не одной | Разовый простой факт — избыточно | Дороже и медленнее одного `WebFetch` | `WebFetch` по конкретным URL |
| `Context7` | Точный синтаксис SDK/API при написании кода | Не применимо, если агент не пишет код продукта сам | — | Официальная документация через `WebFetch` |
| `Bash`/`PowerShell` | Файловые операции, git, локальные команды, обратимые технические шаги — без запроса разрешения, если задача уже начата | Не для веб-поиска; не для суждений, которые принадлежат владельцу (категория 4 Principle выше) | — | — |
| `Agent` (фоновый субагент) | Задача большая, независимая, не обязана держать основной контекст занятым (категория 5 Principle выше) | Мелкая обратимая задача — быстрее сделать самому | Независимый запуск имеет фиксированную стоимость входа даже на тривиальную задачу — не дробить одну задачу на много мелких вызовов | Сделать самому |
| Модель субагента (Sonnet/Opus/Haiku) | Явно указывать модель при каждом запуске, не наследовать по умолчанию; базовая модель — своя, более сильная — только под конкретно названный сложный шаг | Не переключать модель тихо и не эскалировать «на всякий случай» без названной причины | Нет формального правила «задача X → модель Y» — решение по месту, причина называется явно в момент запуска, не по умолчанию | — |

## Fallback

Если ни один инструмент не подходит под задачу — сначала `ToolSearch` (могут быть отложенные инструменты, ещё не загруженные в контекст) с ключевыми словами задачи. Если и это не даёт результата — честно сказать, что подходящего инструмента нет, а не имитировать результат другим инструментом.

## Integration-происхождение

Не список конкретных MCP, а именно правила выбора — «когда Exa, когда Context7, когда Filesystem» и т.д. Реализовано как принцип по категории задачи + implementation-таблица, актуальная на дату создания, а не подгонка под примеры, названные при обсуждении, которые в этой среде не подтвердились. Это прямое требование владельца Engineer, не рыночная находка, обозначено как таковое честно.
