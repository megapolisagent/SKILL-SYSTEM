# opportunity-discovery
## Операционная спецификация capability Opportunity Discovery

> Этот skill не вводит новую capability. Capability объявлена в `CLAUDE.md` →
> Capability Registry и вшита в Reasoning Pipeline (шаг 3) — она обязательна
> там, а не здесь. Этот файл — только исполняемый протокол для неё: если файл
> исчезнет или переименуется, capability в CLAUDE.md всё равно существует и
> требует исполнения каким-то способом. Не путать «Opportunity Discovery» с
> «skill opportunity-discovery.md» — второе лишь текущая реализация первого.

Критерий вызова: пользователь делится новой технологией, моделью, инструментом,
статьёй, видео, GitHub-проектом, MCP, SDK, API или стартапом — материалом,
меняющим пространство возможностей экосистемы.

❌ **НЕ запускается:**
- исправление бага
- рефакторинг
- локальная автоматизация
- ответ на конкретный технический вопрос без появления новой технологии или
  нового класса возможностей (например, вопрос про синтаксис Python/SQL,
  отладка ошибки, точечная правка внутри уже выбранной архитектуры)

Когда критерий совпал — Opportunity Discovery обязательна, не факультативна
(см. `CLAUDE.md` → Reasoning Pipeline, шаг 3). Пропуск этого шага при
совпавшем триггере — незавершённый reasoning, не сокращённый путь. Пропуск
шага при НЕ совпавшем триггере (из списка ❌ выше) — корректное поведение, не
недоработка.

Связь с `context/user_maria.md`: это продолжение уже описанного там паттерна
«философское описание без инженерной спецификации → самостоятельно перевести
концепцию в рабочий контур», но без явного запроса — «новая технология без
запроса → самостоятельно перевести в бизнес-возможности экосистемы».

---

## Layer 1: Reality

Разделять явно: FACT / INFERENCE / UNKNOWN — это ЗНАЕМ / ПРЕДПОЛАГАЕМ / НЕ
ЗНАЕМ из `CLAUDE.md` → Эпистемические маркеры, не новая система, применить
здесь явно. Не пересказывать материал целиком — сжать до сути.

---

## Layer 2: Constraint Shift

Не «что умеет инструмент», а «что перестало быть дорогим, сложным или
невозможным». Смотреть не только внутрь текущих проектов — какие индустрии
это меняет в принципе.

---

## Layer 3: Opportunity Explosion

10–20 идей, без фильтра, без оценки, без ограничения текущими проектами.
Стартовая точка: «если бы у Марии сегодня не было ни одного проекта, что бы
мы построили».

Обязательная поправка (закреплено на практике 2026-07-18): даже без фильтра
каждый пункт должен цепляться за конкретный сценарий или человека — иначе он
превращается в generic listicle и нарушает собственный тест Марии на AI-slop
(«могло бы это написать ChatGPT без доработки»). Широко ≠ пусто.

---

## Layer 4: Ecosystem Mapping

Только теперь открывать `projects/registry.md` и `context/life_context.md` —
не раньше (ошибка, зафиксированная на практике: открытие registry.md до
дивергенции схлопывает Layer 3 обратно к текущей структуре проектов).

Для каждой сильной идеи:
- что усиливает / упрощает / делает ненужным
- какой проект из registry.md выигрывает
- новая capability внутри существующего проекта или новая сущность — см.
  Principle 2 (Test Before Add) в `CLAUDE.md`: не создавать сущности без
  необходимости

---

## Layer 5: Kill List

Отдельный вопрос от Constraint Shift: что после этой технологии Мария лично
может перестать делать — процесс, документ, роль, инструмент, ручная работа,
целый этап производства. Удаление сложности часто ценнее новой
функциональности.

---

## Layer 6: Time-to-Value

Сортировка по Impact × Time-to-Value, не по технологической красоте, не по
novelty, не по сложности. Явно называть трение с уже отложенными
направлениями (см. `context/life_context.md` → «что сознательно не
делается») — не тащить их молча в рекомендацию.

---

## Layer 7: Weekly Experiment

Один эксперимент, не дорожная карта и не список задач. Формат:
«Если бы мы проверяли только одну гипотезу на этой неделе, я бы выбрал...»

---

## Обязательный лог (формат вывода)

```
[OPPORTUNITY DISCOVERY]
Reality: [FACT / INFERENCE / UNKNOWN — по одной строке]
Constraint Shift: [что исчезло]
Opportunity Explosion: [N идей, N >= 10]
Ecosystem Mapping: [проект → выигрыш, для сильнейших идей]
Kill List: [что можно перестать делать]
Time-to-Value: [ранжировка + явно названное трение с отложенным направлением]
Weekly Experiment: [одна гипотеза]
```
